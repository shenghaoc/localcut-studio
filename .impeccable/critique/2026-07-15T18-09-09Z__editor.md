# Design Critique: LocalCut Studio Editor

> Historical audit input captured before the review-hardening changes in this
> branch. The final implementation adds actionable recovery copy, collapsible
> Project/Overlay/Screencast/Tutorial groups, explicit content-badge versus
> chrome-count-pill recipes, and Reduce Motion handling for the recording
> countdown. The remaining autosave, command-palette, and status-history ideas
> below are product opportunities, not claims about this PR's completed scope.

## Anti-Patterns Verdict

**LLM assessment (superseded palette):** This captured an earlier custom-palette
revision. The current product direction keeps the TeXShop-for-video
aesthetic but lets macOS supply the window appearance and control accent. The
remaining assessment still applies: no gradient text, glassmorphism-as-default,
hero-metric templates, eyebrow kickers, side-stripe borders, custom display
fonts, decorative motion, inconsistent component vocabulary, or modal-first
interaction.

**Deterministic scan:** The detector returned empty results — expected, since it targets HTML/CSS/JS and this is a native SwiftUI app. No automated antipattern detection was possible for this surface.

**Visual overlays:** Not applicable — native macOS app with no browser injection path.

## Overall Impression

This is a genuinely well-designed native macOS tool. The current system-adaptive
chrome and user-selected accent reinforce the “shipped with the OS” quality
without visual noise. The keyboard-first power-user path is already strong. The
primary opportunities are in error recovery (making failures actionable), help
discoverability (a command palette or quick-reference overlay would fit the
Developer's Editor aesthetic), and inspector density (progressive disclosure
for the growing number of contextual sections).

## What's Working

1. **Keyboard-first efficiency.** The shortcut vocabulary is comprehensive and well-considered — Space for play/pause (delegated to a window-level handler so it doesn't swallow text input), Cmd+K for split, Cmd+T for transition, Cmd+I for import. Disabled states are used correctly (not hidden) with .help explaining why. The undo/redo titles are descriptive, not generic.

2. **Empty states that teach.** Both the preview ("Import media, then drag a clip to the timeline") and media bin ("Import video or audio to start editing") provide actionable empty states with a prominent bordered button. Jordan the first-timer lands here and knows exactly what to do.

3. **Accessibility investment.** .accessibilityLabel on every icon-only control, .updatesFrequently on the status bar, VoiceOver announcements on status changes, .accessibilityAddTraits(.isHeader) on the segmented rail picker, .isSelected on clips. The accessibility grep shows 26 files with labels — this is not an afterthought.

## Priority Issues

**[P1] Error messages are thin — they report what happened but rarely what to do.** Most error paths set statusMessage to either a hardcoded string or error.localizedDescription. Examples: "Preview build failed: …", "Could not create bookmark for …". These name the failure but offer no recovery step. An editor that prides itself on "honest state" should tell the user what to try next.

**[P1] The inspector is dense and growing.** The inspector Form already conditionally shows: clip properties, speed, colour grading, looks, beauty, audio fades, cover frame, project settings, overlay list, screencast tools, and tutorial finishing tools — all in one scrollable Form. For a new user, this is a wall of sections.

**[P2] No autosave or version browsing.** The editor has Save and Save As with standard shortcuts, but no integration with macOS autosave/version browsing. A crash loses unsaved work.

**[P2] Segmented rail tabs hide contents until clicked.** The side rail uses a segmented picker for Inspector/Audio/Captions/Tools, but a first-time user has no way to know what's inside each tab without clicking through all four.

**[P3] No command palette or quick-help overlay.** The Developer's Editor aesthetic would benefit from a command palette — Cmd+Shift+P to search all actions, reveal shortcuts, and jump to any panel.

## Persona Red Flags

**Alex (Power User):** No autosave or command palette. Export is available from
File ▸ Export and with ⇧⌘E; other editing shortcuts are similarly strong.

**Sam (Accessibility):** Strong VoiceOver support. Timeline clip block navigability unclear. No status message history.

**Riley (Stress Tester):** Graceful empty states. Unclear recovery from rapid undo/redo during rebuilds. Error messages may expose internal details.

## Minor Observations

- Status bar text contrast on .bar background should be verified at smallest Dynamic Type size.
- Two badge styles in use: .thinMaterial (format/safe-zone) vs .quaternary (media count) — verify intentional.
- Recording countdown overlay animation should check accessibilityReduceMotion.
- Timeline scroll position and playhead not persisted across launches.

## Questions to Consider

- What if the status bar showed the last 3 messages instead of only the current one?
- Does the inspector need to show every section at once, or could it use disclosure triangles?
- What would a "confident" version of the empty editor look like — matching the Developer's Editor tone?
